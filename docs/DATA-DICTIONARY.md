# 三联单与标准质量

- 三份 CSV 支持 UTF-8 BOM、UTF-8 与 GB18030。列可重排。原始行号按记录首行计。重复表头仅产生分段计数。空文件、全空白、只剩表头分别返回独立诊断。空串和 `-`、`N/A`、`NULL`、`未知` 是必填缺失。重打凭据 `reprints` 为可选第四份 CSV，缺省时按空通道处理；三份必填原件缺任一通道直接拒收。
- 计量票字段 `ticket,truck,opened,closed,start_l,stop_l,event,fuel,rho,rho_unit,temp_c`。时间带时区，转 UTC，结束必须晚于开始。读数用 L，温度用 °C。`event` 为 `normal`、`wrap` 或 `reset`。签收单为 `ticket,truck,signed_kg,document`，库存表为 `truck,movement,kind,kg`。库存类型为 `opening`、`inbound`、`closing`。签收与库存的输入 kg 须能精确量化成 g。重打凭据字段 `reprint,truck,tickets,document`，`tickets` 用分号列出至少两张同一笔发油的计量票号，凭据按 `reprint` 号去重。
- 计量票和签收单分别用票号去重，库存以车辆和库存单号去重，重打凭据用凭据号去重。规范后完全相同保留首行。冲突保留组内原件与行号，整组不入账。
- 同一罐车的计量票按半开时间窗 `[opened, closed)` 两两比较：前票 `closed` 等于后票 `opened` 的首尾相接不算重叠，照常核算。真正重叠的票用并查集归入同一重叠组，且只在两端读数都已算出标准质量的票之间归组。
- 重打凭据指向的票号必须全部存在且车号一致，否则该凭据标记 `EVIDENCE` 不予采信。凭据成员不越出重叠组、覆盖组内每张票并把整组连通时，整组确认为同一笔发油：组内第一张票为保留票（KEEPER）正常入账，其余票标 `MERGED_DUPLICATE`，两张原票及凭据行号全部留痕可查，库存只按保留票扣一次。凭据不能完整覆盖的重叠组即使各有签收也一律 `OVERLAP_PENDING` 留待核，所属罐车列为争议车。
- 量程版本生效区间左闭右开。当前候选按修订号最大值选取。最大值有并列或起止及中途跨有效裁决变化时挂起。票的止读时刻也需要原量程仍有效。两端读数属于 `[0,量程)`。人工归零挂起。真实回卷须声明回卷并满足旧读数落顶带、新读数落底带，计算量程减旧读数加新读数。另校验单票发放上限。模型只支持一次回卷。
- 标准体积 L 等于观测体积乘 `1 − 0.0008 × (油温 − 15)`。密度接受 kg/m3、kg/L 与 g/L，先转 kg/m3 后按油种检查范围。两者相乘得到 g，使用 Decimal 四舍五入为整克。误差带取绝对下限与质量乘 ppm 后向上取整中较大者。签收差为签收减计量，绝对差等于误差带时算吻合。
- 逐车库存差额为期初加当班入车、减可信计量发放、减期末。可信计量发放只计正常票与重叠保留票；合并掉的重复票不扣，待核重叠票不扣。争议车仍单列已确认发油（含待核重叠票），但不参与合计、不出库存盈亏。对待证签收仍保留可信计量发放，另列缺证及差额。缺唯一库存期初或期末、或出现可定位库存坏行的车辆不参与合计，单列可信计量量。未被匹配的签收单单列。库存差与签收差分别核算。
- 批次键由三份 CSV（含可选重打凭据）的摘要、量程样本摘要、规则与参数组成。清单与五个计算阶段在 SQLite 事务中同时提交。同批复跑命中同一批次，不重复扣库存。签发用规范 JSON 的 SHA-256 做完整性校验，保留异常状态，不改变计量判定。样例和温度模型用于交班数据复算演示。
